# 썸네일 관리자

확인 날짜: 2026-09-30
범위: Entry Debugger 전용

## 사용 흐름

- 디버깅 → 설정 → **썸네일 관리자**를 켠다. 실험실 옆에 독립 탭이 나타난다.
- **현재 썸네일**은 서버에 실제 저장된 이미지다. 새로 고른 이미지의 미리보기와 구분한다.
- 이미지/GIF/영상을 선택하고 **새 썸네일 적용** → 엔트리 **작품 저장** 순서로 반영한다.
- 업로드가 성공한 작품은 새로고침 후에도 기존 서버 이미지를 유지한다.
- **현재 썸네일 유지**는 이전 실험실이나 다른 도구로 올린 서버 이미지를 재업로드 없이 등록한다.
- **제거**는 유지 설정과 임시 선택을 해제한다. 다음 작품 저장에서 엔트리가 자동 썸네일을 만든다.
- **선택 취소**는 새 이미지 선택만 취소한다. 이미 저장된 작품의 유지 설정은 보존한다.
- 저장하지 않은 새 선택은 새로고침하면 사라진다. 기존 GIF/APNG/영상 변환 한도는 동일하다.

## 설정과 저장 범위

- `thumbnailManagerEnabled: false`가 기본값이다. 실험실 OFF와 독립적이다.
- 디버깅 탭만 숨겨도 켜진 관리자의 저장 보호는 계속 동작한다.
- 관리자 OFF 또는 확장 전체 OFF에서는 원래 저장 동작을 사용한다.
- `chrome.storage.local`의 `thumbnailManager.project.<24자리 작품 ID>: true`만 저장한다.
  이미지·영상 본문, 인증정보, 작품 JSON은 보관하지 않는다. 작품마다 별도 키를 사용해
  여러 탭의 서로 다른 작품 설정이 덮어써지지 않게 하고 `storage.onChanged`로 동기화한다.
- 설정은 현재 브라우저의 해당 확장 설치에 한정된다. 다른 브라우저/확장 OFF 상태에서
  작품을 저장하면 엔트리가 서버 썸네일을 다시 만들 수 있다.

## 구현 및 메시지 흐름

- `settings.js`: 정규화, 기본값, 주요 기능 집계.
- `content.js`: 설정 토글과 실험실 바로 다음의 독립 탭, 표시/숨김과 이전 탭 복귀.
- `thumbnail-ui.js`: 서버 미리보기, 기존 변환기 호출, 새 선택/취소/제거,
  유지 설정 읽기·쓰기 및 다른 탭 변경 동기화.
- `thumbnail-override.js`: 새 이미지에 대한 기존 canvas 캡처 훅과 해당 작품의 썸네일 POST 훅.

채널은 `__ENTRY_DEBUGGER_THUMBNAIL__`이다. 같은 window/source/origin만 받는다.

1. `CONFIG {enabled, projects}`: 저장된 유지 대상 ID 목록으로 페이지 훅 구성.
2. `APPLY dataURL` / `RESET`: PNG/APNG 캡처 준비 / 임시 캡처 원복. 응답은 `RESULT`.
3. 새 이미지 저장은 원래 Entry 업로더를 그대로 통과한다. 응답 복제본에서 HTTP 성공과
   JSON 오류 유무를 확인한다. 원래 응답과 body는 소비하거나 변경하지 않는다.
4. 성공 시 `COMMIT {id, project, custom}` → content의 storage 쓰기 완료 → `COMMITTED`.
   새 작품 저장 뒤 이동하기 전에 실제 서버 ID의 유지 설정 쓰기를 기다린다.
5. 저장한 사용자 썸네일에는 `Entry.canvas_.toDataURL` 훅을 해제한다. 이후 저장에서는
   같은 작품의 썸네일 POST만 생략한다. 새 작품/복사본 ID의 첫 업로드는 생략하지 않는다.
6. 생략 시 정상 JSON `Response`를 반환한다. 검증 때 썼던 오류 주입은 사용하지 않는다.
   현재 Entry WASM 업로더는 `Response.json()`을 기다리며 호출자는 그 결과 값을 사용하지 않는다.
   따라서 원래 저장 함수의 화면 복원·저장 완료 처리가 이어진다.
7. `SAVING`, `SAVED`, `SAVE_ERROR`, `SAVE_END`로 UI 상태 갱신. 서버/저장소 오류를
   영구 유지 성공으로 표시하지 않으며 업로드 실패 시 새 이미지로 재시도할 수 있다.

작품 저장 GraphQL, 다른 API, GET/DELETE, 다른 origin의 요청은 그대로 위임한다.
기능 OFF/pagehide 시 원복하며 다른 확장이 뒤에 설치한 래퍼는 덮어쓰지 않는다.
경로/canvas 변경 시 이전 이미지가 다른 작품의 캡처에 사용되지 않게 한다.
이미지가 아직 저장되지 않은 동안의 canvas 추출 대체는 이전 구현과 동일하다.

## 확인한 Entry 동작

공개 배포 코드 `2629-ea83b6654cddf1c2.js`의 프로젝트 저장은 먼저 작품 데이터를 저장한 뒤
`saveThumbNail(id)`를 호출한다. `9076.72bdb7da4743b42e.js`와
`121641580e77227f.wasm`은 현재 canvas를 PNG로 추출하고 JSON POST를 보낸다.
썸네일 주소는 `/uploads/thumb/<ID 앞 4자리>/<ID>.png`로 고정이며 업데이트 시 교체된다.

비공개 테스트 작품에서 2026-09-30 분석 단계에 확인한 결과:

- 일반 저장 후 새로고침/재저장하면 사용자 APNG가 자동 정적 PNG로 덮어써졌다.
- 썸네일 POST를 1회 생략해도 제목 A→B, X좌표 0→120이 저장됐다.
- 이전 서버 APNG 4,548바이트·2프레임은 바이트까지 동일하게 남았다.
- 이는 서버 동작 분석이며 아래 신규 관리자 구현의 실제 서버 설치 검증과는 구분한다.

## 검증

- `npm run check`: 설정 독립성, 저장 후 유지, 새 페이지의 재저장, 제거/기능 OFF,
  신규·복사본 첫 업로드, 실패 응답/저장소 오류, 다른 요청 통과, descriptor/다른 래퍼 보존,
  늦게 끝난 저장이 취소를 되돌리지 않는지 검사한다.
- `npm run review:thumbnail`: localhost:8097에서 실제 제품 UI/페이지 훅을 불러오는 수동 검증 화면.
  Entry 저장 서버와 Chrome storage만 로컬 모형으로 대체한다. 외부 계정·실서버 호출은 없다.
- Chrome UI 확인: 설정 ON → 독립 탭 → APNG 선택/적용/저장 → 새로고침 → 제목/X 변경 저장.
  작품 저장 2회에 썸네일 업로드는 1회였고 현재 이미지는 APNG로 유지됐다.
- 제거 후 세 번째 저장에서 썸네일 업로드가 2회가 되며 실행화면 이미지로 바뀌었다.
  실험실 OFF 상태에서도 관리자가 표시되고 기존 이미지 유지 등록이 가능했다.
- `tools/smoke-thumbnail.js`의 기존 변환/실제 Entry UI 스모크도 새 설정과 탭에 맞췄다.
  이 작업에서는 해당 별도 브라우저 스모크 대신 연결된 Chrome의 로컬 모형을 조작했다.

## 신규 관리자 실서버 검증 (2026-09-30)

작업 폴더의 확장을 새로고침한 뒤 비공개 테스트 작품에서 새 관리자 UI로 직접 확인했다.
이 검증에서는 DevTools 일회성 패치나 오류 주입을 사용하지 않았다.

| 동작 | 실제 서버 결과 |
| --- | --- |
| 기존 서버 이미지 유지 등록 → 제목 C로 저장 | 기존 APNG 4,548바이트·2프레임 유지 |
| 제거 → 작품 저장 | 자동 PNG 17,361바이트·1프레임으로 변경, 정상 저장 완료 |
| 새 APNG 적용 → 작품 저장 | 4,548바이트·480×270·2프레임·0.5초 업로드 성공 |
| 편집기 새로고침 → 제목 D/X좌표 80으로 저장 | 작품 내용 반영, 업로드 직후 APNG와 바이트 동일 |
| 편집기 다시 새로고침 | 제목 D, 엔트리봇 X=80/Y=0 확인 |

- 실험실 OFF 상태에서 진행했으며 관리자는 독립적으로 동작했다.
- 작품은 최종 APNG가 적용된 비공개 상태로 남겼다. 기존 다른 작품은 수정하지 않았다.
- 유지된 APNG SHA-256: `793fd66803af46a1a0e3b79122c69e7f04547234f4185c4c1514068bcb7ad959`.
- 자동 PNG SHA-256: `4b033d7c37811b95f098f5dd18609c3dbc3ba0034d40655dd55099f453053e57`.
- 마이페이지에 표시된 서버 이미지를 내려받아 크기·프레임·재생 시간과 SHA-256을 비교했다.
  원본 검증 기록과 화면은 로컬에 보관하며, 공개 저장소에는 테스트 계정·작품 식별자를 포함하지 않는다.
- 좁은 실제 편집기에서 설정 화면의 아래쪽 스크롤이 관리자 탭에 이어지는 것을 발견해,
  관리자 탭 진입 시 상단의 현재 썸네일부터 보이도록 스크롤을 초기화했다.

## 배포 상태와 한계

- `npm run verify`로 린트, 자동 검사, 개발용/제출용 빌드를 확인했다.
  소스는 다음 배포를 위한 변경사항이며, 확장 버전은 2.7.0을 유지한다.
  이 기능을 포함한 Chrome Web Store 제출은 별도 작업이다.
- 기존 비공개 테스트 작품에서 실제 업로드/제거/새로고침 후 재저장까지 확인했다.
  새 작품·복사본 분기와 실패 응답은 자동 검사로 확인했고, 실제 계정에서 새 작품 생성이나
  저장 실패를 강제로 만들지는 않았다.
- 공식 API가 아닌 현재 저장 구현에 의존한다. Entry의 썸네일 경로·메서드·업로더 응답 처리
  방식이 바뀌면 해당 호환성을 다시 확인해야 한다.
